compression / head-wise

DuoAttention

TL;DR: Every method so far in this catalogue decides which tokens to keep, and applies that decision the same way to every attention head. DuoAttention asks a different question first: does this head even need the full cache? Some heads genuinely attend across the whole context; most, it turns out, barely look past a handful of sink tokens and whatever's recent.

Retrieval heads and streaming heads

Xiao, Tang, Zuo, Guo, Yang, Tang, Fu, and Han's paper splits attention heads into two kinds. Retrieval heads are the ones whose job actually requires seeing the whole context: the kind of head that lets a model answer "what number appeared on page 12" from something read pages ago. Streaming heads do something much closer to what StreamingLLM imposes on an entire model by fiat: attention that concentrates almost entirely on a few initial sink tokens plus whatever's recent, regardless of how far back the rest of the context goes. The difference is this isn't a rule DuoAttention is imposing, it's a pattern the paper found already exists in a trained model, per head, and the point of the method is to detect it and stop paying for cache those heads never use.

Measuring which heads are which

Because it's a property of the head rather than of any one prompt, it can be measured once, offline, and reused. kvpress's DuoAttentionPress.load_attention_pattern() downloads a precomputed per-(layer, key/value-head) score array directly from files hosted in the DuoAttention GitHub repository, but only for a fixed list of checkpoints it recognizes: togethercomputer/Llama-2-7B-32K-Instruct, two Gradient AI long-context Llama-3 checkpoints, Meta's Llama-3.1-8B-Instruct, and both Mistral-7B-Instruct-v0.2 and v0.3. Point it at any other model without setting on_the_fly_scoring=True and the assertion fails outright. The on-the-fly path is kvpress's own addition, and its docstring calls it "experimental": it runs 50 sampled BookSum passages through the model, takes the mean query and key per layer, applies RoPE, and measures the area under the cumulative attention curve for the last token as a proxy for how much that head needs full context.

head_compression_ratio then decides what fraction of all heads, across every layer, get converted to streaming. The lowest-scoring heads go first (an ascending sort over the whole score array), on the reasoning that those are the heads the measured pattern is least confident actually need full context.

Simulated, not measured. There's no real per-head attention pattern here: each head's "how much it needs full context" score is generated locally from a deterministic seed, not downloaded from DuoAttention's real precomputed pattern files. The sink and recent-window sizes are also scaled way down to fit a 29-token demo sentence; real DuoAttention checkpoints default to a 128-token sink and a 256-token recent window.

Masking, not trimming

A streaming head's compress step doesn't shrink the K/V tensors it returns. It computes which (batch, head, position) triples fall in the masked middle (everything between the sink and the recent window) and stores those indices on the module for the attention computation to apply directly, the same indirect mechanism CriticalAdaKV uses on this site. Whether that actually turns into a smaller cache in memory depends on how the serving stack handles those masked indices downstream, not on anything guaranteed by compress() alone.

Where this shines, and where it doesn't

Because the decision is per-head rather than per-token, DuoAttention composes with real token-eviction methods running on top of the same cache: a head kept as "retrieval" can still have its tokens trimmed by any ScorerPress in this catalogue. And the payoff at long context lengths is large: the paper reports up to a 2.55x memory reduction for MHA models and 1.67x for GQA models, decoding up to 2.18x and 1.50x faster respectively, pre-filling up to 1.73x and 1.63x faster, and, combined with quantization, Llama-3-8B decoding a 3.3 million token context on a single A100 GPU. The cost is that it depends on knowing which heads are which for your specific model: the pattern-file path only covers a short, fixed list of checkpoints and needs a network fetch to GitHub at load time, and the fallback "on-the-fly" scoring is explicitly labeled experimental in kvpress's own docstring and costs a full forward pass over 50 calibration samples before you get an answer. Neither is as cheap or as portable as pointing a ScorerPress at an arbitrary model the way most of the rest of this catalogue can.

Real implementation

kvpress implements this as DuoAttentionPress. See the source: duo_attention_press.py. Original paper: Xiao, Tang, Zuo, Guo, Yang, Tang, Fu, Han, "DuoAttention: Efficient Long-Context LLM Inference with Retrieval and Streaming Heads," 2024.
