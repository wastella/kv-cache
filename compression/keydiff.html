compression / similarity-based

KeyDiff

TL;DR: Knorm scores a cached key by its own length. KeyDiff scores it by its direction: how closely it points the same way as the "average" key currently in the cache. Keys that look like everyone else are the ones with the least to lose by leaving; keys that point somewhere distinctive are kept. Like Knorm, it never touches an attention matrix.

Distinctive keys, not big keys

Park et al. observed that geometrically distinctive keys, ones whose direction stands apart from the rest of the cache, tend to earn high attention scores later on. A key that points the same way as most of its neighbors, on the other hand, is redundant almost by definition: several other cached keys already carry roughly the same directional information, so losing any one of them costs little.

KeyDiff turns that into a score without ever computing attention. First it builds an anchor: normalize every cached key to unit length, then average those unit vectors together, which gives the mean direction the whole cache is currently pointing in. Then each key is scored by -cosine_similarity(key, anchor), so a key that's well-aligned with the anchor scores low (typical, evict first) and a key that points somewhere else scores high (distinctive, keep). The whole computation is a mean and a batch of cosine similarities over vectors the model already produced, no queries or attention weights required anywhere.

What kvpress implements, and what the paper actually does

Worth being upfront about: KeyDiff's original paper runs this scoring rule block-wise and iteratively, splitting the sequence into blocks and re-scoring as it goes, rather than computing one global anchor over the whole cache in a single pass. kvpress's KeyDiffPress on its own only does the single-shot, whole-cache version described above; the block-wise iteration is implemented separately, in a wrapper class. To reproduce the paper's actual algorithm, kvpress's own docstring says to compose the two:

press = BlockPress(press=KeyDiffPress(compression_ratio=0.x), block_size=N)

Used alone, KeyDiffPress is the scoring rule the paper is built on, not a drop-in reproduction of the paper's published numbers.

Simulated, not measured. Each token here gets a synthetic low-dimensional "key vector" derived deterministically from its text, standing in for the real head-sized key vector a forward pass would produce. The anchor and cosine-similarity math applied to it is the real KeyDiffPress rule.

Where this shines, and where it doesn't

The paper reports a performance gap under 0.04% against a full, uncompressed cache at an 8K token budget on LongBench with Llama models, and up to a 30% cut in end-to-end inference latency compared to other token-eviction methods it was benchmarked against. Because scoring never looks at an attention matrix, it's also compatible with kernels like FlashAttention that never materialize one in the first place, which some attention-based methods in this catalogue can't say. The tradeoff is the same one Knorm carries: this is a geometric correlation, not a measurement of what any particular query actually needed, so it can't distinguish "usually irrelevant" from "irrelevant so far, about to matter." And without BlockPress wrapped around it, kvpress's version is a simplification of what the paper evaluated, not a direct reproduction.

Real implementation

kvpress implements this as KeyDiffPress, whose score() is -F.cosine_similarity(keys, anchor, dim=-1) against an anchor built from F.normalize(keys).mean(dim=2). See the source: keydiff_press.py, and the block-wise wrapper referenced above: block_press.py. Original paper: Park, Jones, Morse, Goel, Lee, Lott, "KeyDiff: Key Similarity-Based KV Cache Eviction for Long-Context LLM Inference in Resource-Constrained Environments," NeurIPS 2025.
