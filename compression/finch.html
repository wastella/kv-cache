compression / prediction-based

FINCH

TL;DR: SnapKV uses attention from the end of the prompt to predict what matters, but has to guess ahead of time how many tokens that "end of the prompt" window should cover. FINCH removes the guess: it detects exactly where the question starts and sizes the window to match it, automatically, on every request.

A window that has to match the question

SnapKV's observation window is a fixed hyperparameter, window_size, chosen once and applied to every request. That's a mismatch waiting to happen: a three-token question gets padded out with irrelevant prompt tokens if the window is set too wide, and a long, detailed question gets truncated if it's set too narrow. Corallo and Papotti's fix is structural rather than tunable: FINCH expects the input formatted as context + delimiter token + question, and reads the window size directly off wherever that delimiter lands, so the window is exactly as long as the actual question, every time, with nothing to tune.

The delimiter itself never reaches the model. kvpress hooks the embedding layer during prefill, finds the delimiter's position in the input ids, computes window_size as everything after it, and strips the delimiter's embedding out of what actually gets processed. From there the scoring is SnapKV's core idea: average how much attention the window pays to every earlier context token, and keep the top-scorers. FINCH adds one extra step before that averaging: each window position's attention row gets scaled by how many earlier tokens it could see under causal masking, so a window position deeper into the window (which sees more of the sequence) doesn't get diluted relative to one nearer the start. Like SnapKV, the window's own score is padded to the maximum afterward, so ranking can never prune it out.

One more thing FINCH does that SnapKV doesn't: when rerotate_keys is on (the default), surviving keys get their RoPE rotation reapplied as if the kept tokens had always sat contiguously, rather than left at their original positions with gaps where evicted tokens used to be.

Try it

Move question length and watch the outlined window resize with it: there's no separate window-size knob to tune, the window is the question, however long it turns out to be. Darker earlier tokens received more simulated attention from that window and are more likely to survive.

Simulated, not measured. The "attention from the window" here is generated locally with a distance-decay term plus a few random topical-match spikes, the same illustrative stand-in used on the SnapKV page, not extracted from a real model. This demo also doesn't reproduce FINCH's causal-masking correction step or its key re-rotation; both are described above but aren't something a token-keep/evict grid can show.

Where this shines, and where it doesn't

FINCH targets the same shape of workload SnapKV does, long context with a clear question at the end, RAG, document QA, but with one less thing to tune, since the window size is read off the input instead of guessed. The paper reports compression up to 93x without any fine-tuning. The cost is a stricter contract on the input: FINCH needs a literal delimiter token inserted between context and question, which means resizing the model's token embeddings and running a tokenizer update before the press can be used at all, and it needs that context-then-question structure to actually be present. Methods that score every step fresh, like TOVA, or accumulate attention as it happens, like H2O, don't need any assumption about where the "real" question lives in the input; FINCH does, and if the input doesn't have that shape, there's no delimiter to detect and no window to size.

Real implementation

kvpress implements this as FinchPress, whose score() mirrors SnapKVPress with an added normalization step, and whose embed_token_forward_hook detects the delimiter token during prefill to set window_size dynamically. update_model_and_tokenizer() must be called first to register the delimiter. See the source: finch_press.py. Original paper: Corallo, Papotti, "Finch: Prompt-guided Key-Value Cache Compression," TACL, 2024.
