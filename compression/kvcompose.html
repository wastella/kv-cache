compression / structured

KVCompose

TL;DR: Most attention-based methods on this site compute one importance score per token and apply it everywhere. KVCompose lets every attention head score tokens on its own, then reconciles the disagreement between heads two different ways: one that keeps the compressed cache a normal rectangular tensor, and one that doesn't.

Every head gets its own opinion

KVCompose scores tokens from real attention, the same raw material SnapKV and H2O use, but it doesn't collapse that attention down to one number per token right away. During prefill, it re-runs the prompt through the model a second time with the cache already primed, purely to record how much attention each context token receives, per layer and per individual attention head (aggregated across the decoding steps that follow with a configurable mean or max rule). Query heads that share a KV head under grouped-query attention are then pooled back down to that KV head's own score. The result is a tensor of shape (layers, kv_heads, context_len): a genuinely separate ranking of the same tokens for every head, instead of one ranking shared by all of them.

Two more adjustments happen before any eviction decision gets made: optionally weighting each token's score by the norm of its own value vector (add_v_norm, off by default), and adding the mean score across all heads back into every head's own score (add_mean_across_heads, on by default) so one noisy head can't swing a token's fate entirely on its own.

Structured vs. unstructured: what actually differs

Here's the part that's easy to get wrong from the name alone: structured mode does not force every head to keep the identical set of tokens. Each head still ranks tokens by its own score and picks its own top tokens. What structured mode forces is that every head in a layer keeps the same number of tokens, that count decided globally per layer from a composite score (each head's own score curve sorted independently, then averaged across heads rank-by-rank, so the composite reflects how much a given rank position tends to matter across heads rather than raw score levels). A shared count per head is exactly what lets the compressed keys and values for a layer be torch.stack'd back into one ordinary (kv_heads, count, head_dim) tensor afterward, even though which original sequence position landed in slot j can differ from head to head: that's the "composite token" in the name, one cache slot, several heads' worth of independently-chosen content.

Unstructured mode drops that shared-count constraint too: each head gets its own token budget from a genuine global top-k over every (layer, head, token) score at once, so different heads in the same layer can end up keeping different numbers of tokens, not just different tokens. It's the more theoretically faithful version of "let every head decide for itself," but a cache where each head has a different sequence length no longer fits kvpress's normal dense tensor layout, so kvpress implements it by masking out evicted positions in the attention computation itself (masked_key_indices) rather than physically shrinking any tensor.

In unstructured mode the counts themselves can diverge too.

Simulated, not measured. There's no real attention or value vectors behind these two rows. Each token's per-head "importance" is assigned deterministically from its text, and unstructured mode's budget divergence is an illustrative jitter, not a real global top-k. The point being demonstrated, structured alignment is about a shared token count, not a shared token identity, is real, and comes directly from reading kvpress's compress_structured().

Where this shines, and where it doesn't

KVCompose gives you both worlds behind one interface. Structured mode's shared per-head count keeps the compressed cache a plain dense tensor, so nothing downstream (the attention kernel, the serving stack) needs to know compression happened at all, while still letting each head pick tokens by its own attention pattern rather than being forced through one shared SnapKV-style score the way most of this catalogue works. Layer budgets themselves come from the data (the rank-averaged composite curve) rather than a hand-picked shape the way PyramidKV's pyramid is. The costs are real: running the prompt through the model twice during prefill, once normally and once more purely to harvest per-head attention statistics, roughly doubles prefill compute and briefly needs about 2x the KV cache memory, which kvpress's own implementation warns about directly in its logs. Scoring also requires eager attention, so it can't run the scoring pass through a fused or flash-attention kernel. And unstructured mode's better theoretical fit comes at the cost of needing a modified attention path rather than a literal smaller tensor, extra plumbing an ordinary top-k eviction doesn't need. As of this writing kvpress has only tested it against Llama, Qwen2, and Qwen3 architectures.

Real implementation

kvpress implements this as KVComposePress. See the source: kvcompose_press.py. Original paper: Akulov, Sana, De Domenico, Si Salem, Piovesan, Ayed, "KVCompose: Efficient Structured KV Cache Compression with Composite Tokens," 2025.
