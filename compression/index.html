Compression methods

Architecture

  • GQA / MQA
    Share key/value heads across query heads and the cache shrinks before a single token is ever evicted.
  • MLA: Multi-Head Latent Attention
    Compress every token's keys and values into one small latent vector, and reconstruct the full per-head versions on the fly.

Inference-time

  • StreamingLLM
    A fixed-size cache for infinitely long streams: an early attention sink stays forever, a trailing window stays current, and nothing in between survives. No attention scores involved anywhere in the rule.
  • H2O: Heavy-Hitter Oracle
    Tracks how much cumulative attention each cached token has actually earned since it entered the cache, rather than trusting its position. A handful of "heavy hitters" end up accounting for most of the mass.
  • TOVA: Token Omission Via Attention
    No running total, no memory of earlier steps: eviction is decided fresh every decode step, purely from which cached token the current query attended to least right now.
  • Expected Attention
    Forecast how much future queries will attend to each cached key from the statistics of queries the model has already issued, before those future queries ever arrive.
  • CriticalKV
    Take an existing score and rescale it by how much a token's value actually moves the model's output, not just how much attention it received.
  • CapKV
    Score each cached token by how much unique, query-relevant information its value vector would leave behind if evicted.
  • DuoAttention
    Classify each attention head as retrieval or streaming once, then give retrieval heads the full cache and streaming heads only a sink and a recent window.
  • SnapKV
    Score how much attention the end of the prompt pays to everything before it. Do it once, right after the prompt is read, before a single token is generated.
  • FINCH
    SnapKV-style prediction, but the observation window auto-sizes to match the question instead of using a fixed hyperparameter.
  • ChunkKV
    Score tokens individually, then evict in contiguous chunks instead of scattered picks, so surviving context stays intact rather than fragmented.
  • LagKV
    No attention weights at all: score each partition of the cache by how it compares statistically to the partition that comes right after it.
  • KeyDiff
    Score each key by how closely it points toward the average key direction, and evict the ones that look the most typical, no attention weights involved.
  • Knorm
    The cheapest scoring rule in the catalogue: a key vector's own length turns out to predict how much attention it'll get later, so length alone decides who gets evicted.
  • CUR
    Score cached tokens by both key and value magnitude, judged against nearby tokens rather than against the whole sequence at once.
  • KVzip
    Ask the model to repeat the context back to itself, then measure which cached KV pairs it actually needed to do that.
  • RestoreKV
    Spend part of the compression budget on a handful of learned tokens trained to restore what a full cache would have known.
  • KVzap & Fast KVzip
    Two small trained models, one from NVIDIA and one from NAVER, that approximate KVzip's expensive reconstruction signal cheaply enough to run every step.
  • Q-Filter
    Score cached keys against a filter vector learned offline for the exact model being served, instead of a heuristic formula computed at request time.
  • PyramidKV
    How much cache budget does each layer even need? Give early layers more room than late ones, instead of one flat ratio everywhere.
  • SimLayerKV
    Some layers already behave like StreamingLLM on their own. Detect those "lazy" layers per input and only compress those.
  • LU-KV
    Give every layer and every attention head its own cache budget, pulled from a curve fit offline instead of one hand-picked shape.
  • DMS
    Pick a score threshold instead of a compression ratio, and let however many tokens clear the bar be however many survive.
  • ThinK
    Prunes an entirely different axis: every token stays, but the least useful dimensions get stripped out of each vector, the same channels dropped for every token in a head.
  • Quantized KV cache
    Keep every token, but store each surviving number in fewer bits, instead of throwing anything away.
  • Compactor
    Blend a geometry-only leverage score with a non-causal chunked-attention score to decide what survives.
  • CaM
    Instead of dropping an evicted token outright, fold its value vector into the kept neighbor right after it.
  • MergingPress
    Instead of just deleting an evicted token, fold its value into whichever surviving token looks most similar to it.
  • KVCompose
    Let every attention head disagree about which tokens matter, then reconcile that disagreement in a way that still fits a standard cache layout.

Combinators & wrappers

  • AdaKV
    Instead of one global top-k across the whole cache, lets each attention head keep its own top-scoring tokens, with a safeguard so no head gets compressed to nothing. Source: adakv_press.py.
  • ComposedPress
    Runs several presses in sequence, each operating on what the previous one left behind, e.g. evict tokens with SnapKV, then prune dimensions with ThinK. Source: composed_press.py.
  • ChunkPress & BlockPress
    Apply any scoring method independently within fixed-size chunks (ChunkPress) or iteratively block by block (BlockPress), instead of scoring the whole sequence at once. Source: chunk_press.py, block_press.py.
  • KeyRerotationPress
    After any press evicts tokens, re-applies rotary position embeddings so the survivors' positions are contiguous again instead of leaving gaps in the rotation. Source: key_rerotation_press.py.
  • PerLayerCompressionPress
    Applies a manually specified list of per-layer compression ratios to any underlying method, the general case PyramidKV's fixed pyramid shape is one specific instance of. Source: per_layer_compression_press.py.
  • DecodingPress family
    Runs compression only during decoding (not the initial prompt read), on a rolling buffer, every few steps. PrefillDecodingPress pairs a separate prefill-time and decode-time press; CompressionRatioDecodingPress derives the decode-time budget from a ratio instead of a fixed size. Source: decoding_press.py.
  • RandomPress
    Evicts tokens uniformly at random. Not a real strategy, a null hypothesis: any method worth using should beat this at the same compression ratio. Source: random_press.py.

Systems

  • PagedAttention
    Stop pre-allocating one giant contiguous buffer per sequence. Allocate fixed-size pages on demand instead, the way an OS pages virtual memory.
