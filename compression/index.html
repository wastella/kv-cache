Compression methods

The KV cache gets smaller at a few different points in a model's life: some choices are baked in when it's trained, some are bolted on at inference time, and some come from how a serving system manages memory. Different stage, same goal — this page groups all of it together, plus how you'd know any of it actually worked.

Inference-time methods

Ported from NVIDIA's kvpress, which implements 40+ of these behind a single API. Each page here explains one method's intuition, shows the real scoring logic it's built on, and lets you run it against the same sample sentence so you can compare methods directly. These are all "presses" — bolted onto an already-trained model, not adjustable at any other stage.

  • StreamingLLM position-based
    Keep a handful of "sink" tokens plus a sliding recent window. No content scoring — pure position rule.
  • H2O — Heavy-Hitter Oracle attention-based
    Track cumulative attention per token during generation; a small set of "heavy hitters" earns most of it — keep those.
  • SnapKV prediction-based
    Use attention from the last few prompt tokens to predict which earlier tokens will matter, and compress before generation even starts.
  • Knorm norm-based
    Score cached keys by nothing but their own L2 norm — no attention weights needed at all, the cheapest content-aware method here.
  • PyramidKV layer-wise
    Give early layers a bigger cache budget than late ones instead of one flat ratio everywhere — a different axis of compression entirely.
  • TOVA — Token Omission Via Attention attention-based
    Score tokens from only the current decoding step's attention, recomputed fresh every step — simpler state than H2O, more volatile.
  • ThinK dimension-pruning
    Prune the least useful channels inside each kept key vector instead of dropping whole tokens — shrinks vectors, not the sequence.
  • Quantized KV cache quantization
    Keep every token, but store each one in fewer bits. Stacks with any eviction method above rather than competing with it.

Architecture-level

Decided when the model is trained, not adjustable afterward — the cache is smaller by construction rather than by a scoring rule applied later.

  • GQA / MQA — Grouped/Multi-Query Attention architecture-level
    Share key/value heads across multiple query heads so the cache is smaller by construction — baked in at training time, not adjustable afterward.
  • MLA — Multi-Head Latent Attention architecture-level
    Compress each token's keys and values into one small shared latent vector, reconstructed on the fly — DeepSeek's approach to a smaller cache without dropping heads.

Systems

How a serving system allocates and manages cache memory — orthogonal to which tokens or bits get kept.

  • PagedAttention systems
    Stop pre-allocating one giant contiguous buffer per sequence — allocate the cache in fixed-size pages instead, like an OS's virtual memory.

Evaluation

Removing part of the cache always saves memory. Whether it's safe depends entirely on how you measure quality afterward.

  • Evaluating compression methodology
    Removing half the cache always saves memory. Whether it's safe depends entirely on how you measure quality afterward.
