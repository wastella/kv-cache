compression / layer-wise

SimLayerKV

TL;DR: PyramidKV gives every layer a different-sized budget but still decides which tokens survive the same way everywhere. SimLayerKV goes further: some layers get no compression at all, and others collapse down to just a sink plus a recent window, because a check run per layer, per input, finds they're barely using the rest of their cache anyway.

Lazy layers

Zhang, Du, Du, Pang, Gao, and Lin ("SimLayerKV: A Simple Framework for Layer-Level KV Cache Reduction," arXiv 2410.13846) observed that certain attention layers, for a given input, consistently behave like StreamingLLM already does by design: they mostly attend to a handful of initial "sink" tokens plus a nearby recent window, and barely touch anything in between, for the entire length of generation. They call these lazy layers. The rest of the layers keep attending broadly across the full context and get left alone entirely.

kvpress's SimLayerKVPress detects laziness with a direct check: take the attention the last n_last query tokens pay (1 token by default, kvpress fixes this to match what the code comments call "SKLV-decode"), average it, and sum up how much of it lands on the first n_initial tokens (4 by default) plus the most recent n_recent tokens (1024 by default). If that sum exceeds lazy_threshold, the layer is lazy for this input: keep only the initial and recent tokens, discard the rest of that layer's cache. If it doesn't, keep the whole thing, no compression for that layer at all.

Two details matter for using this in practice. First, lazy_threshold defaults to 1.0, which the source treats as "off": at exactly 1.0 (or on any sequence shorter than n_initial + n_recent + n_last), no compression happens regardless of what the attention check would say. Second, the right threshold is genuinely model-specific, not a universal constant: kvpress's own docstring recommends 0.9 for Llama3, 0.65 for Llama2, 0.8 for Mistral, and 0.85 for Qwen. Different model families turn out to be lazy to different degrees, so this has to be calibrated per model, not assumed. Like DMSPress, compression_ratio here is a read-only property computed after a forward pass, not something you set.

Simulated, not measured. Each layer's "attention paid to sink + recent" value is assigned deterministically per layer, purely to demonstrate the lazy/not-lazy decision rule. The paper does find that a given layer's laziness is consistent across a generation for a fixed input, but which specific layers tend to be lazy in a real model isn't something this demo attempts to reproduce, that's a real empirical result, not a formula we can fake here.

Where this shines, and where it doesn't

SimLayerKV catches a kind of redundancy PyramidKV's depth-based budgeting can't: two layers at the same depth can behave completely differently on the same input, one lazy, one not, and this method can tell them apart, per input, rather than assuming a shape based on depth alone. It's training-free, and the paper reports (per its abstract) roughly a 5x KV cache compression ratio combined with 4-bit quantization at about a 1.2 percentage point score drop on LongBench, tested on LLaMA2-7B, LLaMA3-8B, and Mistral-7B.

The tradeoffs are specific to being a binary, per-layer decision rather than a graduated, per-token score. A layer that's mostly lazy but genuinely needs one token buried in the middle has no way to keep just that token, it's sink-plus-recent or the full cache, nothing in between. The lazy_threshold default of 1.0 means the method does nothing at all until you pick a real value, and as covered above, the right value is model-specific and has to be found per family, there's no safe universal default the way Knorm or TOVA need no tuning to do something reasonable out of the box. And detecting laziness itself still costs a real, if cheap, attention computation over the last n_last query positions, done fresh at every check.

Real implementation

kvpress implements this as SimLayerKVPress, whose compress() calls is_lazy() per layer and either slices keys/values down to sink + recent or returns them untouched. See the source: simlayerkv_press.py. Original paper: Zhang, Du, Du, Pang, Gao, Lin, "SimLayerKV: A Simple Framework for Layer-Level KV Cache Reduction," 2024 (the authors later replaced this arXiv entry with a follow-up paper, LightTransfer, so the link above is pinned to the original v1 to keep pointing at SimLayerKV specifically).
