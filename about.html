About

I built kv/cache while doing my own research into KV cache compression. The papers and source code are all out there, but I found the intuition easier to build by watching a small set of tokens get evicted in front of me than by reading a scoring formula on its own. This is the resource I wish I'd had, made public in case it's useful to someone else working through the same material.

Relationship to kvpress

The catalogue is a companion to NVIDIA's kvpress, an open-source (Apache-2.0) library that implements 40+ KV cache compression methods behind one API for Hugging Face Transformers models. The scoring logic on each catalogue page is written to match kvpress's real implementation, and every page links to the exact source file it's based on.

This site is independent and unofficial — it is not affiliated with, endorsed by, or reviewed by NVIDIA. If something here misrepresents how a method actually works, that's my error, not theirs; let me know.

Why these methods, and why in this order

kvpress groups its presses into a few conceptual families: rule-based eviction by position, scoring by observed or predicted attention, norm-based scoring, layer-wise budget allocation, dimension pruning, quantization, and low-rank/merging. The catalogue currently covers eight methods spanning most of those families — StreamingLLM, H2O, and SnapKV were the first stop because they're the most-cited starting points in the compression literature, and the rest were added to show how differently the other families approach the same problem. Merging/low-rank methods (e.g. CaM, KVzip) aren't covered yet.

Why some things aren't in the catalogue

Everything in the catalogue is a kvpress "press" — something applied to an already-trained model at inference time. Some of the field's most important ideas for shrinking a KV cache don't fit that description: they're decided when a model is trained, not when it's served (grouped/multi-query attention, DeepSeek's latent attention), or they're not compression at all (how a serving system like vLLM allocates cache memory, how anyone measures whether a compression method actually held up). Mixing those into the catalogue would misrepresent kvpress, so they live in a separate Concepts section instead.

A note on the demos

The interactive sandboxes run entirely in your browser — nothing is sent to a server, and no model is actually doing inference. Where a method's scoring depends on real attention weights (H2O, SnapKV), the demo uses a small simulated score generator that mirrors the shape of real attention distributions, so you can see the algorithm's logic clearly without needing to load an actual model. That's flagged on each page.
