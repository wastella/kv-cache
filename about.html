About

Why I made kv/cache

I built kv/cache while doing independent research into KV cache compression. The papers and source code are all out there, but I found the intuition easier to build by watching interactive demonstrations on small sets of tokens than by reading a scoring formula on its own. This is the resource I wish I'd had, made public in case it's useful to someone else working through the same material.

The catalogue is a companion to NVIDIA's kvpress, an open-source library that implements all of the compression methods found on this website. I used their library to tinker around with various methods when I first started learning about kv-caches, and I would highly recommend it.

However, this site is independent and unofficial: it isn't affiliated with, endorsed by, or reviewed by NVIDIA. If something here misrepresents how a method actually works, please let me know.

A note on the demos

The interactive sandboxes run entirely in your browser. Nothing is sent to a server, and no model runs live in your browser. Where a method's scoring depends on real attention weights (H2O, SnapKV), the demo uses a small simulated score generator that mirrors the shape of real attention distributions, so you can see the algorithm's logic clearly without needing to load an actual model. That's flagged on each page. The one exception is basics's cache-growth demo. Its Q/K/V numbers are real, but pulled from an actual GPT-2 (124M) forward pass computed offline and shipped as static data.
