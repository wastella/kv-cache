beyond the catalogue

Concepts

Everything in the catalogue is an inference-time "press" from kvpress — something you bolt onto an already-trained model. The ideas here are different in kind: some are decided when a model is trained, not when it's served, and some aren't compression at all, but the systems and evaluation context that explains why the catalogue matters and how you'd know if any of it actually worked.

  • GQA / MQA — Grouped/Multi-Query Attention architecture-level
    Share key/value heads across multiple query heads so the cache is smaller by construction — baked in at training time, not adjustable afterward.
  • MLA — Multi-Head Latent Attention architecture-level
    Compress each token's keys and values into one small shared latent vector, reconstructed on the fly — DeepSeek's approach to a smaller cache without dropping heads.
  • PagedAttention systems
    Stop pre-allocating one giant contiguous buffer per sequence — allocate the cache in fixed-size pages instead, like an OS's virtual memory.
  • Evaluating compression methodology
    Removing half the cache always saves memory. Whether it's safe depends entirely on how you measure quality afterward.
Different axis, same goal. The catalogue asks "which tokens survive." These pages ask "what else determines how big the cache is in the first place" and "how do we know any of this is safe."
