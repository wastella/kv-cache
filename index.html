An interactive guide to KV-cache compression

A transformer model keeps a growing cache of key and value vectors so it never has to recompute attention over the whole prompt again. Over time that cache can become costly. This guide walks through what it is and various methods to compress it, with small interactive demos.

    Prefill vs. decode, why the cache grows linearly, and why that becomes a memory problem at long context lengths.

Compression

  • Architecture
    Decisions made when the model is trained, so the cache is smaller from the very first token, before any eviction logic runs.
  • Inference-time
    Applied to a model you didn't train yourself, no fine-tuning needed. Each method picks what to keep from whatever cache the architecture hands it.
  • Systems
    Not about deciding what to keep, but where it lives once kept: this is what turns a smaller logical cache into more sequences actually served.
  • Evaluation
    Every method here saves memory. Whether that's a good trade depends on how you check the damage afterward.
