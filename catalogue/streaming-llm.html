StreamingLLM

Keep the first few tokens forever, keep a sliding window of the most recent tokens, and drop everything in between. No attention scores, no learned model — just a rule about position.

The attention sink

Xiao et al. noticed something odd while trying to run LLMs on infinitely long streams: if you naively evict old tokens once a context window fills up, quality collapses almost immediately — even though those old tokens didn't seem semantically important. The cause turned out to be structural, not semantic. Softmax attention forces every query to distribute weight across all keys, even when nothing is relevant, so models learn to dump the "leftover" attention onto a few early tokens as a kind of no-op — and it's specifically the early tokens that end up absorbing it, since causal masking means they're the only positions every later token can always see. Evict those sink tokens and the whole attention distribution destabilizes.

The fix: never evict the first n_sink tokens (4 is typically enough), no matter how long generation runs. Combine that with a sliding window of recent tokens — which any autoregressive model needs for local coherence — and the cache stays a fixed size indefinitely.

The double-bordered tokens at the start are the sink; everything else is kept only if it falls inside the trailing window.

Where this shines, and where it doesn't

StreamingLLM is nearly free to run — there's no scoring pass, so it adds no compute overhead, and it's a natural fit for streaming or chat workloads with effectively unbounded length. The tradeoff is exactly what you'd expect from a position-only rule: it has no idea what's in the middle of the context. A critical fact stated once, early in a long document, is gone the moment it scrolls out of the window — sink tokens or not. It's a strong default, not a general solution to "what matters."

Real implementation

This demo's compute() mirrors kvpress's StreamingLLMPress.score() almost exactly: keep n_sink, mask everything before the trailing window to zero. kvpress's own docstring notes that this scoring step alone doesn't fully reproduce the paper — surviving tokens still carry their original RoPE positions with a gap where the evicted middle used to be, so matching the paper exactly means pairing it with the KeyRerotationPress wrapper, which re-rotates the kept keys onto contiguous positions after pruning. See the source: streaming_llm_press.py. Original paper: Xiao et al., "Efficient Streaming Language Models with Attention Sinks," 2023.
